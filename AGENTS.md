# GodMode: notes for contributors and for agents working in this repository

This file is read by Codex, Cursor, OpenCode and Antigravity when you work *on* GodMode itself. It is not part of the plugin that users install; for that, see `skills/`.

## What this repository is

An engineering-discipline plugin for AI coding agents: 33 skills under `skills/`, one bootstrap hook under `hooks/`, and one manifest per harness at the repository root. The skills are the product; everything else exists to deliver them unchanged to Claude Code, Antigravity, Codex, Cursor, OpenCode and Copilot CLI.

## Rules for changing skills

1. Read `docs/plans/2026-10-25-godmode-2-design.md` section 4 and `skills/writing-skills/SKILL.md`. They define the template and the voice.
2. Skill bodies name actions, never harness tools. Harness specifics live only in `skills/using-godmode/references/<harness>-tools.md`.
3. Every fact that can change (a tool name, a flag, a URL, a limit) comes from a current source you fetched, with the URL in an HTML comment. Nothing from memory.
4. `skills/using-godmode/SKILL.md` must stay under 9,000 characters: the session-start hook injects it whole and Claude Code caps that at 10,000.
5. Run `node scripts/validate.js` before committing. It fails on the mistakes above.

## Rules for changing the plugin layer

- `hooks/hooks.json` keeps the plugin root in escaped double quotes; `hooks/run-hook.cmd`, `hooks/session-start` and `hooks/doctor` stay executable (`git update-index --chmod=+x`) and LF-only. `bash tests/test-hooks.sh` checks all of this.
- One version everywhere: `node scripts/bump-version.js <semver>` updates every manifest listed in `scripts/version-files.json`.
- README pictures are generated by `scripts/readme_assets.py` and the hero by `scripts/make_hero.py`; edit the scripts, not the SVG or PNG files. CI fails if the committed assets differ from the script output.
- Do not add a root `plugin.json`, a root `hooks.json`, or a root `AGENTS.md` meant as an agent rule: Antigravity loads plugin rules only from `rules/`, and a root hooks file in Claude format breaks its loader.

## Pull requests

One problem per PR, with the failing behaviour you observed and the harness and version you observed it on. Changes to skill wording need before/after evidence from a real session or an eval run (`claude plugin eval .` when the suite exists). Run the validator and the tests; CI runs them on Linux, macOS and Windows.
